### 근접 비비기 해결 — CombatUnit 3가지 개선

**진단**: 4 근접 vs 1 적 시나리오에서 4명이 한 점에 몰려 비비는 현상.
원인: 같은 타겟·같은 자연 접근각·약한 분리력·동맹끼리만 분리.

**솔루션 1: 각도 분산** — `_compute_desired_attack_position(target, allies, eff_range)`
- 자기 위치에서 target 향한 자연 접근각을 시작점
- 같은 target을 노리는 동맹들의 점유각을 수집
- `TARGET_RING_MIN_ARC_DEG=60°` 이내 동맹 있으면 ±30°·±60°·±90°·±120° 순으로 빈 각도 탐색
- desired position = target.position + Vector2.from_angle(chosen) × APPROACH_RATIO × eff_range
- MOVE 상태에서 target.position 대신 desired로 이동

**솔루션 2: 타겟 부하 분산** — `_select_target(enemies, allies)`
- `_find_nearest` 폐기, score = `1000 - distance - load × 120` (`TARGET_LOAD_PENALTY=120`)
- 같은 적을 노리는 동맹 1명당 120점 감점 → 자연스러운 1:1 분산
- 4명 vs 3명이면 한 명만 더블링, 나머지 1:1

**솔루션 3: 분리 강화** — `_apply_separation(allies, enemies, delta)`
- 시그니처에 `enemies` 추가 → 동맹 + 적 모두 분리 (적 라인 못 뚫음)
- 단 `target`인 적은 제외 (사거리 끝에서 접촉 가능해야 공격됨)
- `SEPARATION_STRENGTH 120 → 200` (분리력 67% 증가)
- ATTACK 상태에서도 `ATTACK_SEPARATION_FACTOR=0.20` 비율로 약한 분리 → 자리 잡은 후 겹침 미세조정

**기타 변경**:
- 헬퍼 추가: `_angle_diff(a, b)` (`fposmod` 기반 [-π, π] 정규화), `_is_angle_blocked(angle, blocked, min_arc)` — static
- `target.position` 정확히 향하지 않으니 `raw_dist`는 사거리 판정용으로만 유지, 이동 거리는 `desired_dist` 사용
- `sign` 같은 GDScript built-in 이름 회피 (`dir_sign`)
- 각도 탐색 루프 버그 픽스 — 마지막 attempt가 체크 없이 끝나던 문제 수정

## 3. 결정 / 합의 사항

- **MIN_ARC = 60°**: 4명 attacker까지 자연스러운 분산 (이상적 90° 보다 좀 좁아 여유). 5+ 명이면 일부 겹침 발생 가능 — 그때 조정.
- **TARGET_LOAD_PENALTY = 120**: 거리 점수 단위가 px와 같아서 동맹 1명당 120px 감점. 적이 200px 멀어도 부하 0이면 우선됨.
- **ATTACK_SEPARATION_FACTOR = 0.20**: ATTACK 상태에서 분리 효과를 1/5로. 너무 강하면 공격 자세 못 잡고 흔들림.
- **타겟 적은 분리 대상 제외**: 타겟에 너무 가까워 안 닿는 현상 방지. 다른 적은 분리.

## 9. 퀘스트 시스템 정식화

이전 "수락 = 즉시 골드" placeholder를 폐기. 정식 퀘스트 시스템.

### 신규 클래스 (2종)
- **`scripts/data/quest.gd`** — `Quest extends Resource`. Kind enum (WIN_BATTLES / HIRE_UNITS / DEFEAT_BOSS), target_value, progress, reward_gold, giver_role/name, description, detail, reward_text, accepted_at_chapter/stage. `is_complete()`, `progress_text()`, `kind_label()`, `summary()`.
- **`scripts/data/quest_tracker.gd`** — `QuestTracker extends RefCounted` 정적 헬퍼. `on_battle_won(run, was_boss)`, `on_unit_hired(run)`, `grant_reward(run, quest)`. RunState.active_quests를 훑어 진행도 누적.

### RunState 확장
- `active_quests: Array[Quest]` (role당 1개 제한)
- `completed_quest_ids: Array[StringName]`
- `battles_won_total: int`, `units_hired_total: int` (누적 카운터)
- `add_unit_data` → units_hired_total 증가 + `QuestTracker.on_unit_hired` 호출
- `note_battle_won(was_boss)` 메서드 추가 — battle_screen에서 호출
- `active_quest_from_role(role) -> Quest`, `has_active_quest_from(role) -> bool`

### Tracking Hook 연동
- **battle_screen `_on_battle_ended`** — PLAYER_WIN 시 `GameState.run.note_battle_won(is_boss)` 한 줄 추가
- **RunState.add_unit_data** — 영입 시 자동 트래킹 (모든 영입 경로 자동 반영: hub 고용 / treasure / event)

### NPC 조우 3-state 분기
이전 단일 본문 + 수락/떠나기 → 상태별 본문 + 가변 버튼:

| 상태 | 본문 | 버튼 |
|---|---|---|
| **신규 제안** | "[설명] / [상세] / [보상: N G]" | 수락 + 떠나기 |
| **진행 중** | "[진행 중] / [상세] / [진행도 N/M 보상 N G]" | 떠나기만 |
| **완료** | "[완료!] / [상세] / [수령 가능한 보상 N G]" | 보상 수령 + 떠나기 |

`_apply_meet_to_ui`가 `active_quest_from_role(role)` 조회 → null → 신규 제안, 있으면 is_complete()로 분기.

### 역할별 퀘스트 템플릿

`QUEST_TEMPLATES_BY_ROLE` 사전 — 4 역할 × 2 템플릿:

| 역할 | 템플릿 |
|---|---|
| 길드장 | 노상 정리(3승, 100 G) / 보스 토벌(보스 1, 150 G) |
| 조합장 | 상단 호위(2승, 70 G) / 용병단 보강(영입 2, 80 G) |
| 상인 | 도로 정리(1승, 40 G) / 용병 추천(영입 1, 30 G) |
| 주민 | 마을 수호(1승, 25 G) / 마을 청년 추천(영입 1, 20 G) |

### 흐름 예시

1. 길드장 그리젤다 만남 → "노상 정리 의뢰 (3승 / 100 G)" 제안 → 수락
2. 전투 3번 진행 (각 승리마다 quest.progress++)
3. 다시 길드장 만남 → "[완료!] 노상 정리 의뢰" 표시 → 보상 수령 → +100 G

### 부수 사항

- 같은 role에서 1 active quest만. 한 번 받으면 그 role의 다른 NPC가 와도 진행 중 표시.
- 보상 수령 후 active_quests에서 제거 → 같은 role 다음 방문 시 새 템플릿 제안.
- 수락 시점에 `Time.get_ticks_msec()`로 고유 id 부여.
