**1) `rest_screen`에서 체력 회복이 안 됨** — `GameState.run.heal()`로 폐기된 `RunState.health` 필드(런 HP 게이지)를 회복 중이었다. R4 합의에 따라 런 HP 시스템은 없고 유닛 HP carry over만 존재.

- 휴식 1회당 1유닛(`TARGETS_PER_REST=1`) 회복 — `OwnedUnit.heal_full()` 호출 (HP 풀 + INJURED→READY)
- 풀 HP 유닛·DEAD 유닛은 회복 불가 (버튼 disable, 사유 텍스트 표시)
- 부상 유닛은 카운트다운 남은 스테이지 표시

**2) `battle_screen` 사이드바가 max HP만 표시 → "최대체력으로 배치되더라" 인식**
- 사이드바 버튼 텍스트가 `owned.source.max_hp`만 표시했음 (carry-over current_hp 무시)
- → `owned.get_starting_hp(max_hp)`로 current/max 둘 다 표시 (`HP 50 / 100`)
- 드래그 프리뷰도 동일하게 current/max 표시
- 셀(placed)은 이미 `get_starting_hp` 사용 중이라 변경 없음

**3) Mock data 최소화 — encounter도 디스크 우선**
- `_make_mock_encounter()`가 디스크에 7개 인카운터 .tres 있어도 항상 mock 사용 중이었음
- → `_load_encounter_from_disk()` 추가 (`resource/encounters/` 무작위 1개 선택), mock은 로딩 실패 시 폴백
- 플레이어 유닛 mock은 이미 `owned_units.is_empty() && disk_count==0` 조건으로 보호 중 (변경 없음)

### 맵 단순화 — 사용자 피드백 ("거미줄처럼 복잡, 화면 꽉 참")

**MapGenerator 리팩토링** (12 depth × 4 lanes 고정 → 가변 패턴)
- `generate(rng, lanes_per_depth: Array[int] = [1, 2, 1, 3, 2, 1])`
- 첫/마지막 depth는 자동으로 1 lane으로 강제 (시작·보스 단독)
- 마지막 depth는 BOSS 고정, 그 외엔 `_pick_kind` 가중치 분포 (BATTLE 55% / ELITE 15% / SHOP 12% / EVENT 10% / REST 5% / TREASURE 3%)
- 보스 직전(`d == total_depth - 2`)은 REST 가중치 45%로 ↑ (회복 기회 제공)
- 인접 layer 간 엣지: 각 src가 1-2개 dst에 연결, **공간 근접도(정규화 lane)** 기준으로 가까운 dst 우선 → 거미줄 X
- 고아 dst(들어오는 엣지 0개)는 임의 src에서 보강

**map_screen 컴팩트 레이아웃**
- 이전: `avail = size - PADDING*2`로 화면 전체에 분산
- 변경: 절대 step 사용 (`X_STEP=120, Y_STEP=90`) + 화면 중앙 정렬 + `MIN_MARGIN=(120, 100)` 보장
- 각 depth의 lane 수에 맞춰 세로 가운데 정렬 (1 lane이면 중앙, 2 lane이면 ±0.5*Y_STEP, 3 lane이면 ±Y_STEP)
- info 라벨에서 폐기된 `RunState.health/max_health` 표시 제거 → "Chapter X / Gold: Y / Depth: Z" 형식

## 3. 결정 / 합의 사항

### 시너지 엔진 Tier 치환 (이전 라운드에서 결정, 오늘 인지)
같은 (applies_to_type, requires_adjacent_type) 쌍의 룰이 매칭되면 **min_adjacent 가장 큰 1개만 적용** (TFT 식). 시트 수치는 "이 티어에서의 총 보너스"로 해석. 다른 쌍 사이는 여전히 합산. → `battle-flow.md` / `synergy-axes.md` 갱신 권장 (보너스 합산 룰 변경분).

### 적 인카운터의 power target 5x 상향
실제 플레이어 유닛 카탈로그(power 150-200/명) 기준으로 적 power 목표값 재설정. 적 총 power = 플레이어 빌드의 50-70% 수준.

### Tier 2 시트는 별도 콘텐츠 스코프
`Tier2_sheet.xlsx`는 unit/synergy의 tier 2가 아니라 **별도 데이터 카테고리**:
- `items_cargo` — CargoItem (shape/effect/sell_price)
- `events_special` — 특수 이벤트 (title/body/choice_a-c)
- `story` — 스토리 텍스트 (chapter/body)

별도 스코프라 오늘 자동 채움 보류 — 사용자 디자인 방향 합의 후 진행 예정.
