## 3. 결정 / 합의 사항

### 배틀 시스템 기획 1번 차원 (편성 페이즈 UX)
- 5×3 그리드에 적·플레이어 마주보기 (한 화면 위/아래)
- 페이지 넘김 X — 보드는 영구 상태, 화면 들어오면 현재 배치 그대로
- 부상/사망 유닛 = 보관함(Storage)에 격리, 상태 아이콘 뱃지 (✓/⚠/☠)
- 사이드 패널: 보관함 ⇄ 아이템 토글 (한 공간 공유)
- 시너지 실시간 미리보기 (아이콘 + 호버 디테일)
- 명시적 "전투 시작" 버튼 — 그 전까지는 자유 편성·아이템 할당
- 같은 유닛 두 번 배치 가능 (오토체스식 별도 인스턴스)
- 사망 유닛 버리기는 **쉼터(여관)에서만**

### 배틀 시스템 기획 5번 차원 (적 시스템)
- 적 라인업: **카탈로그 + ±20% 변동** (slot variation_pool로 표현)
- 적 시너지: **플레이어와 다른 5개 패턴 전부** 채용 (effect_type enum)
- 적 유닛: **별도 `EnemyUnitData`** (플레이어 UnitData와 분리)
- 인카운터 난이도: **power_score 자동 산정** (적 유닛 합)
- 적군도 자체 시너지 받음 (`enemy_board` 별도 운영)
- mock 데이터로 진행, 실제 카탈로그는 추후 사용자 전달

### 일일 보고서 운영 규칙 (확정):
  - 위치: `docs/daily-reports/YYYY-MM-DD.md`
  - 트리거: 사용자가 "오늘 작업 정리해" 류의 트리거를 주면 작성
  - 성격: 그 날 무엇을 했는지의 **타임라인성 로그**. 디자인 결정 같은 큰 단위는 기존 `docs/session-reports/`에 별도 보관
  - 구조: 6섹션 (오늘 한 일 / 변경 파일 / 결정 / 환경 메모 / 다음 작업 후보 / 미해결)
  - 파일명: `YYYY-MM-DD.md` (토픽 suffix 없음)
  - 커밋 정책: **그날 작업 커밋과 동시 커밋** (별도 커밋 만들지 말 것)
