## 1. 사용자 입력 요약

3개 축:
- 소속 국가: 벤, 크렘, 아르덴, 넬름
- 직업: 보병, 창병, 궁병, 석궁병
- 유형: 군인, 모험가, 용병

확장: 아이템으로 인한 추가 시너지 가능.

친화 매트릭스:
- 벤 → 보병, 창병, 군인
- 크렘 → 보병, 궁병, 모험가
- 아르덴 → 궁병, 석궁병, 용병
- 넬름 → 창병, 석궁병, 모험가

## 3. 채택한 시너지 발동 해석

> 국가 X 유닛은, 자신의 친화 태그(직업/유형)를 가진 유닛이 8방향 인접에 있을 때 강화된다.

→ 시너지의 **주체는 국가 유닛**. 인접 유닛 자신은 그 룰로 보너스 안 받음(자기 국가 룰로 별도 발동 가능).

이 해석은 혼합 편성을 의도적으로 디자인하게 만든다. 같은 국가만 모아도 친화 직업/유형이 안 맞으면 시너지가 약함.

## 4. 데이터 모델 확인

기존 `SynergyRule`이 이미 다축을 자연스럽게 처리한다:

```
applies_to_type = NATION_VEN          # 자기 식별(축1)
requires_adjacent_type = CLASS_INFANTRY  # 인접 조건(축2)
```

`SynergyEngine.compute`는 그대로 동작. 12개 룰만 `.tres`로 만들어지면 끝.

## 5. 의도적으로 미룬 것

- **12개 SynergyRule `.tres` 파일 생성**: 보너스 수치를 모르고 만들면 더미 데이터만 양산. 유닛 카탈로그 확정 → 밸런싱 1차안 → `.tres` 일괄 생성 순서가 효율적.
- **누적 효과 결정**: 인접 친화 2개·3개일 때 보너스가 누적되는가? 현재 룰 구조는 고정 보너스만 표현. 누적이 필요하면 룰을 다단계로 만들거나(`min_adjacent` 별), `per_stack_bonus` 필드를 추가.
- **글로벌 트레이트(TFT 스타일) 지원**: 현재는 인접 기반만. 필요해지면 `SynergyRule.scope` 필드 추가.

## 6. 다음 세션 시작 시 권장 순서

1. **유닛 카탈로그 작성** — 각 유닛이 (국가, 직업, 유형, 기본 스탯, 비용) 세트.
   - 최소 16개(국가×직업 1개씩) 권장. 가능하면 국가별 다양성도.
   - 유닛 ID 컨벤션 정하기 (예: `ven_pikeman_01`).
2. **밸런싱 1차안** — 친화 룰의 보너스 % 값 결정.
3. **`.tres` 일괄 생성** — Claude가 코드로 자동 생성 or 사용자가 Godot 에디터에서 수동. 12개 룰 + N개 유닛.
4. **헤드리스 시뮬레이션 테스트** — 무작위 보드 × 무작위 적군으로 100회 돌려서 결과 분포 보기.

## 7. 알려진 이슈 / 노트

- `synergy_types.gd`의 `AFFINITY` Dictionary는 `Dictionary` (untyped) — Godot 4의 typed Dictionary가 4.4+에서 안정화되면 `Dictionary[StringName, Array[StringName]]`로 좁힐 수 있음.
- `validate_axes()`는 호출 비용이 작지만 hot path(전투 루프)에서 매 프레임 부르진 말 것. 에디터 툴/디버그용.
- 단독 친화(벤·군인, 아르덴·용병)는 의도된 비대칭인지 확인 필요. 의도라면 두 국가에 빌드 정체성을 강하게 만드는 좋은 디자인.
